# DYNOSHI Render Service — free, self-hosted Short renderer

Renders the daily DYNOSHI anime Short (vertical 1080×1920 MP4) with **zero paid
services**: the Hindi voiceover is generated by Microsoft Edge TTS (free, no
account) and the video is rendered by [Remotion](https://www.remotion.dev/)
(React → MP4). In production this runs on **GitHub Actions**, triggered by
**Make.com**; Make receives the finished file back (kept under 5 MB, Make's
free-plan file limit) and uploads it to YouTube through its verified
"DYNOSHI YouTube" connection.

No copyrighted anime clips or images are used anywhere — all visuals are
generated (animated gradient scenes), and the audio is an original AI voice
reading an original script.

## Pipeline

```
Make.com (daily scenario)
  │  1. AI module writes the day's Hindi script + SEO pack
  │  2. HTTP module → GitHub repository_dispatch "render-short"
  ▼
GitHub Actions (.github/workflows/render.yml)
  │  3. edge-tts: script → public/voiceover.mp3  (hi-IN-SwaraNeural)
  │  4. Remotion render: AnimeShort composition → out/short-raw.mp4 (1080×1920)
  │  5. ffmpeg re-encode → out/short.mp4  (~650 kbps video, target < 5 MB)
  │  6. MP4 uploaded as workflow artifact "short-mp4"
  ▼
Make.com
     7. Downloads the artifact MP4 and uploads it to DYNOSHI via its
        YouTube "Upload a Video" module (title/description/tags from step 1)
```

## The contract — what Make sends

`POST https://api.github.com/repos/<owner>/<repo>/dispatches`

```json
{
  "event_type": "render-short",
  "client_payload": {
    "title": "Black Clover S2 Episode 7 \"Beyond Despair\" Explained in Hindi | Noelle vs Megicula Full Fight",
    "script": "Kya aap soch sakte ho ki ek insaan apni sabse badi takleef ke saamne bhi ruk jaaye? ..."
  }
}
```

| Field    | Meaning                                                                 |
|----------|-------------------------------------------------------------------------|
| `title`  | The day's SEO title. Shown on the opening title card (~first 2 s).      |
| `script` | Full voiceover script, plain text. Becomes the edge-tts narration and is auto-split into caption chunks (~5 words each, timed across the audio). |

The same shape is the Remotion composition's props contract:

```ts
{ title: string, scriptText: string, audioFile: string /* file in public/ */ }
```

Composition length is **derived from the generated audio** (`calculateMetadata`
reads the MP3 duration), so any day's script length just works.

## The video design (`src/AnimeShort.tsx`)

- **Animated gradient scenes** — six generated colour palettes crossfading
  every ~9 s with drifting light blobs and a vignette. No external images.
- **Title card** — the day's title on a card over the first ~2 s while the
  voiceover starts.
- **Captions** — big bold white text in a dark pill, chunked from the script
  and timed proportionally across the voiceover, with a pop-in per chunk.
- **Progress bar** — thin gradient bar along the bottom.
- **DYNOSHI watermark** — small channel name at the top.

## Run it locally

```bash
# 1) Python voiceover (one-time venv setup)
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 2) Node dependencies
npm install

# 3) Voiceover for any script file (default: pilot-script.txt)
.venv/bin/python scripts/make-voiceover.py            # → public/voiceover.mp3 (+ .srt timings)
#    args: [script.txt] [out.mp3] [voice]   voice default hi-IN-SwaraNeural, alt hi-IN-MadhurNeural

# 4) Render the pilot (props in pilot-props.json)
npx remotion render src/index.ts AnimeShort out/short-raw.mp4 --props=./pilot-props.json

# 5) Shrink under 5 MB — pick the video bitrate from the duration:
#    total budget ≈ 4.6 MB ⇒ ~650 kbps for a 60 s Short, ~250 kbps for ~114 s.
ffmpeg -y -i out/short-raw.mp4 -c:v libx264 -b:v 250k -maxrate 280k -bufsize 560k \
  -pix_fmt yuv420p -c:a aac -b:a 64k out/short.mp4
# (the GitHub Actions workflow computes this bitrate automatically)
```

On small machines render at 720×1280 instead of 1080×1920 with
`--scale=0.6667` (and optionally `--fps=24`); the composition itself stays
1080×1920 so GitHub Actions renders full resolution.

## Files

| Path | What |
|------|------|
| `src/AnimeShort.tsx` | The `AnimeShort` composition (props-driven, generated visuals only) |
| `src/Root.tsx` | Composition registration; length follows the voiceover MP3 |
| `scripts/make-voiceover.py` | edge-tts voiceover generator (see its header for the transport note) |
| `.github/workflows/render.yml` | `repository_dispatch: render-short` → voiceover → render → <5 MB → artifact |
| `pilot-script.txt` / `pilot-props.json` | The Black Clover pilot script + props used for the local proof render |
| `requirements.txt` | Python deps (`edge-tts`, `websockets`) |

## Pilot proof (2026-11-09, local VM)

End-to-end run with the Black Clover pilot script succeeded:

- Voiceover: `hi-IN-SwaraNeural`, **112.94 s**, 677,664 bytes MP3 (24 kHz mono),
  with word-boundary timings covering the script start to finish.
- Composition metadata: AnimeShort, 1080×1920 @ 30 fps, 3,419 frames (113.97 s,
  derived from the audio).
- Local render at 720×1280 (`--scale=2/3`, 30 fps): raw MP4 16,027,472 bytes.
- Final re-encode: **4,445,108 bytes (4.45 MB)**, 720×1280, 113.98 s,
  H.264/AAC — saved as `~/workspace/youtube-auto-system/sample-pilot-short.mp4`.

## Known notes

- **Roman Hindi:** the pilot script is Roman (Latin) Hindi. The hi-IN voices
  read it as written, word for word — verified for the pilot via the
  word-boundary timings edge-tts returns. Pronunciation of Roman Hindi is less
  natural than Devanagari; if quality matters later, have the AI module output
  the same script in Devanagari and feed that to edge-tts instead — no other
  change needed (captions could stay Roman).
- **edge-tts transport:** `scripts/make-voiceover.py` speaks the Edge TTS
  WebSocket protocol directly (reusing edge-tts' token/SSML helpers) because
  edge-tts' aiohttp transport fails behind some egress proxies. It also
  honours `SSL_CERT_FILE`/`https_proxy` env vars when present and is a no-op
  on normal networks / GitHub Actions.
- **Licence:** Remotion is free for companies up to 3 people; rendering in CI
  for this channel is within the free licence at time of writing.
